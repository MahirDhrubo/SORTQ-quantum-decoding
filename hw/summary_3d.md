# Test 3d (reduced): closed-loop simulation of engine_top_pf2

## Setup
- **Design under test:** engine_top_pf2, VNU_PASSES = 1, STORAGE = LUTRAM (behavioural model of the LUTRAM arrays), simulated with Verilator 5.054.
  - It is the whole engine: ctrl_pf, the state memories, round_step_pf2, conv_check, commit and the 720 gamma lanes.
  - The only simulation change is `sim3d/engine_top_pf2_sim.sv`, generated by `mk_sim_engine.py`. It puts the gamma lanes in LOAD mode (LFSR_MODE = 0) and adds two load ports (`g8_ld`, `g8_ld_data[type][pos]`). The generator prints the full diff: module name, 2 ports, 2 lines in the gamma_src instance.
- **Problem the engine implements here:**
  - W = 13 rounds, win_t = 0, last_r = 12, commit over C = 13 rounds (no syndrome carry).
  - One window is the whole 12-round circuit (13 detector rounds, 936 checks, 8,784 errors). That is exactly the Test 1b X decoder.
  - The engine's other simplifications (no window sliding; slot = window index; prior-file row = round) don't come into play with one window.
- **Software reference:** relay_bp int4.2.8 round sweep with the Test 1b settings (`golden.make`), each shot decoded alone: iterations, success, the full decoding (8,784 hard decisions) and the 12 observables (O · decoding).
- **g8 (LOAD mode):** the software re-seeds its γ RNG at every decode, so every shot uses the same g8 vector per leg.
  - The vectors for legs 0–9 are taken from the 'L' records of the golden dumps.
  - Measured: legs 0 and 1 are identical in all 5 dumps that contain them: shot 53 (10 legs), the 3 golden shots (p = 0.003), and a new p = 0.002 dump of Test 1b shot 484. So g8 depends neither on the shot nor on p.
  - Whenever ctrl issues an init step (first iteration of a leg) for round g, the testbench loads the current leg's g8 of home round g into the lanes, in the cycle before the step starts.
- **Priors:** clip(floor(2·LLR + 0.5), −15, 15) per error, loaded through the prior load port. The table has one value per (type, home round); this is asserted for every error, at both p.
- **Decode-start state (gap found, not fixed in RTL):** leg 0 needs the marginal memory M(−1) = L0, and engine_top_pf2 has no hardware path that writes it. The testbench writes L0 into both marginal banks directly (backdoor) before `start`. Everything else is reset or written through the engine's own ports: the prior file and the syndromes.
- **Shots** (all converge in software; "converged in leg 0" = iterations ≤ 80):
  - **Golden:** Test 2a shots 96, 106 and 53. Shot 53 is itself one of the three golden shots, the 580-iteration one, so this is 3 distinct shots.
  - **Initial random set:** 45 leg-0 + 5 legs-1–3 shots per p, from the first 40,000 Test 1b shots (seed 20261114).
  - **Extended set:** 450 leg-0 + 50 legs-1–3 shots per p (seed 20261115), excluding the initial ones.
  - Typical short decodes are favoured: 90% are leg-0 shots.
  - All random shots were regenerated with the Test 1b sampler calls. Measured: the software iterations equal the Test 1b trace for all 1,100.
- **Run:** server, nice 10, at most 4 cores (Verilator build with 4 jobs; simulation on 1 thread).
  - Build: 220 s.
  - Simulation: 21.7 s for the initial 103 shots (3,005 iterations); 170.6 s for the 1,000 extended shots (22,877 iterations).

## Bugs found and fixed
The first closed-loop run failed on all 103 shots: the engine never converged and ran into the testbench's cycle limit. engine_top had only been synthesized, never simulated.

A new debug mode (`+VEC`) compares the engine's live round_step inputs, in the second cycle of every step, with the Test 2a golden step vectors, which give the hardware-memory contents round_step should see. It found:

1. **v2c_o0 prev write-back** (engine_top_pf2, and the same code in engine_top and engine_top_pf):
   - **Bug:** the prev update of step i rewrites the whole slot word i − 1 of the v2c_o0 memory. For the 3 one-round types (T01, T03, T09), which have no prev update, prev_v2c is 0, so their stored v2c were overwritten with 0. Symptom: from iteration 1, 432–864 wrong v2c_o0 inputs per step.
   - **Fix:** the prev write merges two-round-type edges from the prev update with the other edges from the cur write of the same slot. The cur word is held in a register (`lc_v2c_o0`, plus `lc_q` for VNU_PASSES 2).
2. **Prev write of step 0** (window slot −1, which wraps to slot 15): gated off. Step 0 has no prev group.
3. **Testbench issue, not an engine bug:** commit's `obs_valid` only means "not cleared since start". The testbench now waits for the commit beats (`cm_run`) plus the 2-cycle pipeline.

**Remaining differences:** with the fixes, the only differences left against the golden vectors are the sign of zero (−0 vs +0) on forwarded c2v messages. The VNU treats −0 as 0, so they have no effect.

**The fix changes the synthesized design:** about 15,840 extra FFs, plus a 7,920-bit 2:1 mux on the prev write path. The Test 2c post-route numbers for engine_top / engine_top_pf / engine_top_pf2 are for the unfixed design; I have not re-synthesized.

### Cycles (measured in simulation, every shot)
- **Normal iteration:** 26 cycles (iter_start to iter_start) = 13 round steps × 2 cycles. The convergence check of iteration t is hidden under iteration t + 1.
- **Leg-end iteration** (the last iteration of a relay leg; not overlapped, by design): 36 cycles = 26 + 10, where 10 = conv_req delay (VNU_PASSES + 3 = 4) + conv_check (5) + ctrl turnaround (1).
- **Decode start:** 1 cycle from `start` to the first iteration.
- **Decode end:** 10 cycles after the start of the last (discarded, speculative) iteration.
- **Commit:** 16 cycles after `done` (13 beats + pipeline).
- **Exact for all 1,103 shots:** cycles(start → done) = 1 + 26·n + 10·(leg ends) + 10, with 0 residual.
- **Against the 2c formula** (13 rounds: 13 × 2 + 5 = 31 cycles per iteration):
  - measured 26 for a normal iteration and 36 for a leg-end iteration;
  - over a whole decode, 26.15–31.5 cycles per iteration, the upper end for very short decodes (2 iterations), where the fixed 11 start / end cycles weigh most;
  - at the confirmed engine_top_pf2 P1 clock of 146.2 MHz (pre-fix), 26 cycles = 177.8 ns per iteration.

## What this means
- **Closed-loop agreement:** the integrated engine decodes complete shots exactly like the int4.2.8 software decoder. That includes relay legs with real g8 vectors (up to 10 legs on shot 53), the overlapped convergence check with discarded speculative iterations, and commit.
  - It took two engine fixes to get there. Both were in the integration (memory write-back), not in the verified blocks.
- **Timing model confirmed:**
  - The 26-cycle iteration of the overlapped design and the 10-cycle cost at each leg end are exact in simulation.
  - The 2c formula with 5 cycles per check is pessimistic for normal iterations (31 vs 26) and optimistic at leg ends (31 vs 36).
- **Before hardware use, two items are open:**
  - a hardware path for M(−1) = L0 at decode start;
  - re-synthesis with the v2c_o0 fix.

## Not tested
- **Windowed operation:** W = 12 sliding windows with C = 8 commit and the syndrome carry. Only one window covering all 13 rounds was run.
- **Other variants:** VNU_PASSES = 2, BRAM storage, and the LFSR gamma mode (LOAD mode only).
- **Decode-start initialization in hardware:** done by the testbench (backdoor), as described above.
- **Long decodes:** shots needing more than 10 legs (no g8 vectors beyond leg 9), and non-converging shots (the 18,080-iteration cap).
- **The NR_MIN guard of ctrl_pf:** never active, since 13 rounds ≥ NR_MIN.
- **Timing and area after the fix:** not re-synthesized.
- **Gate level:** only RTL simulation with behavioural memories.

## Update (2026-11-14): hardware decode-start path
- engine_top_pf2 now fills M(−1) = L0 itself at `start` (W = 13 cycles + 1; details in `hw/synth/summary_2c.md`, section "2c re-synthesis (3d fixes)").
- The testbench backdoor is off by default (`+BACKDOOR` to enable).
- **Re-run without the backdoor:** 3 golden + 200 random shots (`sim3d/shots_init.txt`, log `sim3d/sim_3d_init.log`): **203 shots, 0 mismatches**, 180 converged in leg 0.
- Decode cycles are now 14 + 1 + 26·n + 10·(leg ends) + 10.
